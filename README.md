## Abstract
The use of deep learning in high-risk application domains, under regulatory frameworks such as the EU AI Act, requires a precise characterization of the model's decision-making mechanisms. The existing literature provides limited quantitative and qualitative comparisons of explainability across widely adopted deep learning architectures.
We conduct a systematic evaluation of explainability in three representative model families: Convolutional Neural Networks (CNNs), Vision Transformers (ViTs), and Vision Mamba (ViM) state-space models.
Unlike existing studies, which are predominantly based on qualitative evaluations, we quantify the alignment between the model's attention and human visual perception using eye-tracking data treated as ground truth. We evaluate the models in two different domains: fine-grained classification (CUB-200-2011) and medical imaging (MIMIC-CXR). Using architecture-specific explainability (XAI) methods, including GradCAM, ScoreCAM, and AblationCAM for CNNs, ViTLRP for ViT, and MambaLRP for ViM, we measure the fidelity of model saliency maps to human gaze using Jensen-Shannon similarity, Chi-square similarity, and Pearson correlation.
Our results reveal distinct attention dynamics: CNNs tend to exhibit a more global focus, with spatially more diffuse saliency maps that correlate well with human perception in general contexts, while ViTs demonstrate fine-grained, patch-level attention, often focused on discriminative microfeatures. The Mamba architecture exhibits biased behavior, achieving good explainability results in medical tasks, while exhibiting divergent intensity distributions in natural images.
We further analyze the effect of backbone freezing and ensemble strategies on model interpretability. The results highlight how architectural and training choices influence the alignment between model saliency and human visual attention.

## Installation

git clone --recurse-submodules https://github.com/CaregnatoGianluca/VisionExplainability.git
cd VisionExplainability

#### 0. create the conda environment
conda create -n XAI python=3.10 -y
conda activate XAI
#### Install PyTorch Runtime
conda install pytorch==2.1.1 torchvision==0.16.1 torchaudio==2.1.1 pytorch-cuda=11.8 -c pytorch -c nvidia -y

#### Install Matching Compiler & Headers
conda install cuda-nvcc=11.8 cuda-cudart-dev=11.8 cuda-libraries-dev=11.8 cuda-cccl=11.8 gxx_linux-64=11 -c nvidia -y

export CUDA_HOME=$CONDA_PREFIX
export PATH=$CONDA_PREFIX/bin:$PATH
export LD_LIBRARY_PATH=$CONDA_PREFIX/lib:$LD_LIBRARY_PATH

#### Install all the dependencies
pip install setuptools==69.5.1
pip install -r requirements.txt --no-build-isolation

#### Install MambaLRP ensuring no conflicts
cd external/MambaLRP
pip install -e . --no-deps
cd ../../

## Structure
*NetworkManager* is the core of the project: it encapsulates every model/architecture in a unified interface.

Folders:
- DatasetLoader: contains all the scripts to load different datasets
- CNN/Mamba/Transformer: contain the scripts to train/test/run explainability of the relative model/architecture
- CUB: Contains the CUB-200_2011 dataset

Each model folder (i.e. CNN) has a training notebook, evaluation notebook and explainability notebook.
Changing architecture, these notebooks differ a bit, but the main structure is the same. What differs is:
- training parameters
- explainability methods
Each folder also has scripts to easily interface different architectures to the main notebooks, and also modified versions of scripts of other repositories (cited in the scripts).

Explainability is computed thanks to the functions in *heatmap_similarity_metrices.py*.

The final computation of explainability stats is done in the notebook *stats.ipynb*.

Ensemble tests are executed in the notebook *ensemble_test.ipynb*.
